# Blink TUI 体验与视觉升级方案 (v2.0)

## 1. 背景与目标
Blink 已经具备非常完整的底层逻辑：后台异步扫描、快速缓存、完整的快捷键体系（`Shift+I`、`Shift+O` 等）。
目前的痛点主要在于 **“展现形式（TUI 风格）”** 和 **“局部交互摩擦（详情页动作层级）”**。
作为效率工具，Blink 的下一阶段目标是：**提升视觉的现代化质感（Premium Feel），并通过布局重构消除不必要的视图跳转**。

---

## 2. 核心问题诊断（基于现有架构）
在阅读了完整的 `CLAUDE.md` 与 `README.md` 之后，总结出以下问题：
1. **割裂的视图体验**：目前有独立的“列表视图”和“详情视图”。用户在列表视图可以使用 `Shift+I` 快速打开 IDE，但按 `Enter` 进入详情视图后，却需要用方向键 `↓` 去选择 "Open with IDE" 并回车。相同的操作，不同的心智模型。
2. **详情页信息层级混乱**：在 13 行的详情面板中，**操作动作**（如 Pull Latest、Commit）与**只读信息**（如 Path、Git URL）、**可编辑项**（Alias、Tags）混排在一起，没有视觉上的区隔。
3. **屏幕空间利用率低**：列表项占用两行，底部留有大量空白；详情页也只占用了不到一半的屏幕高度。
4. **视觉质感单薄**：缺少面板（Panel）、边框（Border）等容器感设计，信息漂浮在纯黑背景上，缺乏现代终端工具（如 Lazygit、Textual App）的精致感。

---

## 3. 交互与布局重构：引入“双栏联动布局”

为了串联所有功能，最大化发挥 Blink 的效率，**强烈建议彻底废除“全屏切换”的详情页，改为【左侧列表 + 右侧详情/操作】的“双栏布局 (Split-screen)”**。

### 3.1 核心工作流：一切都在同一屏内完成
- **左侧（List View）**：保持现有的双行列表样式，依然支持 `/` 呼出实时搜索。
- **右侧（Detail Panel）**：随着左侧光标的移动，右侧面板**实时无缝更新**当前选中项目的详情。
- **全局快捷键穿透**：所有高频动作（`Shift+I`, `Shift+O`, `Shift+P`, `Shift+U`, `Shift+C`）变成**全局可用**。无论焦点在左侧还是右侧，随时按下即可执行。

### 3.2 右侧详情面板 (Detail Panel) 结构设计
将原来的 13 行列表，重构为带有边框包裹的模块化区域：

```text
╭─ 📁 基础信息 (Metadata) ─────────────────────╮
│ Name:   blink                              │
│ Path:   /Users/russell/workingspace/blink  │
│ Git:    https://github.com/russell/blink   │
│ Status:  main ● +2 ↑1                     │
╰────────────────────────────────────────────╯
╭─ 🏷️ 本地标记 (Local Markers) ────────────────╮
│ Pinned: ★ Yes                              │
│ Alias:  my-blink                           │
│ Tags:   [python] [tui]                     │
│ Desc:   A lightweight TUI to scan...       │
╰────────────────────────────────────────────╯
╭─ 🚀 快捷操作 (Shortcuts) ────────────────────╮
│ [Shift+I] IDE  [Shift+O] Finder  [C] Commit│
│ [Shift+P] 路径 [Shift+U] Pull    [T] tloop │
╰────────────────────────────────────────────╯
```

### 3.3 焦点切换与交互逻辑 (Focus & Interaction)

在双栏布局下，我们需要优雅地处理“浏览”与“编辑”的焦点切换逻辑：

1. **实时同步 (Sync)**：默认情况下，**焦点在左侧列表**。用户按 `↑` / `↓` 浏览列表时，右侧面板会**实时、同步**刷新显示当前高亮项目的数据，无需按下任何确认键。
2. **切入编辑区 (Focus Right)**：当用户想要修改右侧的“本地标记”时，按下 **`Tab` 键** 或 **`→` (右方向键)**，焦点从左侧列表穿梭至右侧的【本地标记】面板。此时，左侧列表的高亮状态变暗，右侧面板边框变亮。
3. **面板内选择与编辑 (Select & Edit)**：
   - 焦点来到右侧后，用户按 `↑` / `↓` 可以上下选择 `Pinned`、`Alias`、`Tags`、`Desc` 这四个选项。
   - 选中 `Pinned` 时，按 `Enter` 直接切换 Yes/No 状态。
   - 选中其他三项时，按 `Enter` 进入**输入模式**，底部弹出光标进行文本编辑。保存（Enter）或取消（Esc）后，焦点仍然留在这个选项上。
4. **切回列表 (Focus Left)**：在右侧面板时（非文本输入态），按下 **`Esc` 键** 或 **`←` (左方向键)**，焦点会立刻返回左侧的仓库列表。

## 4. 视觉风格升级 (Aesthetics)

### 4.1 引入现代化边框与圆角 (Prompt-Toolkit Box/Frame)
利用 `prompt_toolkit` 的 `Frame` 控件，为左侧列表和右侧各个区块添加优雅的圆角边框 `╭ ─ ╮`。
- **焦点状态高亮**：当前拥有焦点的一侧（通常是左侧列表），边框使用**主高亮色**（如青蓝色 `#58a6ff`）；非焦点侧使用**暗灰色**（`#30363d`）。

### 4.2 Nerd Fonts 图标系统
在信息展示中加入 Nerd Font 图标，大幅提升界面的“现代感”和“阅读效率”：
- **列表前缀**：`📁`（普通）、`★`（置顶）
- **Git 状态**：保留当前的 `●`, `○`, `↑`, `↓`，在分支前加 `` (Branch icon)。
- **操作提示区**：`󰨞 IDE` ` Finder` ` Path` ` Pull`

### 4.3 色彩体系优化
基于现有 GitHub Dark 主题进一步优化语义色彩：
- **Repo Name**：使用高亮白色或浅蓝色。
- **Path**：使用低对比度的暗灰色（Dim），降低视觉干扰。
- **Status Badge**：增强对比度，Clean 为绿（Green），Dirty 为橙（Orange），Ahead/Behind 为黄（Yellow）。
- **底栏 (Footer)**：常驻显示最核心的快捷键组合，采用反白或暗底高亮。

## 5. 分步实施计划 (Roadmap)

1. **Phase 1: 视觉与层级分离 (UI Polish & Flatness)**
   - 维持现有视图结构不变。
   - 引入 Nerd Fonts，调整色彩。
   - 在详情页中，隐藏顶部 5 行纯动作行（IDE/Finder等），改为在详情页底部永久显示全局快捷键提示，强迫用户使用 `Shift+I` 等快捷操作，保留仅需查看和编辑的信息行。
2. **Phase 2: 双栏布局重构 (The Ultimate Split-screen)**
   - 修改 `app.py` 中的布局容器，将单页模式变更为左右分割的 `VSplit`。
   - 左侧为 RepoListControl，右侧为使用 `Frame` 包裹的 DetailPanel。
   - 绑定光标移动事件（在 `cursor_up`/`cursor_down` 中调用更新），实现右侧详情的实时渲染。
3. **Phase 3: 完善编辑交互 (Inline Edit)**
   - 在双栏模式下，定义进入右侧编辑态的入口（例如选中项目后按 `e` 键或 `Enter`），聚焦到对应的 Alias/Tags 输入框。
